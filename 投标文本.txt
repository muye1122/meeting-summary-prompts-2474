【详细方案】
Understanding: This is a documentation-only engagement. The buyer needs two reusable prompt templates plus worked examples that turn a meeting transcript into a traceable post-meeting summary. The first template extracts structured facts from one numbered segment using meeting metadata; the second merges all segment results into a single summary while keeping source ids. The core risk is factual drift: invented names, invented dates, invented amounts, or conclusions that cannot be traced back to a segment. The design therefore uses a closed-world rule at both stages, a speaker-code whitelist, explicit relative-date handling, and a review-queue-only output state.

Plan:
1. Write the segmentation template with YAML-style frontmatter (feature code, version, template type, inputs, outputs) and a fixed five-array JSON schema with per-item segment ids.
2. Write the reduce template with the same frontmatter contract, the deduplication rule table, a closed-world constraint and the summary JSON schema.
3. Define the segment-result schema: task, owner code (speaker code or TBD), due (explicit absolute date or TBD), due raw (original wording), evidence quote (60 characters maximum), plus direction, speaker code and resource descriptions.
4. Define the summary schema with preserved segment-id unions, per-item date status, locked draft metadata, and a persons-referenced whitelist check.
5. Author fictional minutes A with a meeting date, containing a repeated decision, an amount and one resolvable relative date.
6. Author fictional minutes B without a meeting date, containing relative dates, an amount, demand and supply leads, and no invented aliases.
7. Write the design note covering dedup keys, date conversion rules, verbatim amount policy and name whitelist policy; implement the Node verification script with four checks.
8. Run the script, capture real output into the verification record, and assemble the bid text.

Data sources: No external datasets are used. All content is compiled from the ticket brief; all meeting titles, speaker roles, person names, dates and monetary figures are fictional placeholders. No real personal information, no real company names and no overseas data calls.

Why me: I deliver precise, reproducible documentation artifacts with machine-checkable evidence. The two-level structure mirrors a map-reduce pipeline: the extraction stage never merges across segments, and the reduce stage never invents facts, so every summary line has a verifiable origin. The verification script uses only built-in Node modules, so the buyer can rerun all four acceptance checks offline with no installation step.

Implementation: No special access, API key, live transcription service or database is required. Deliverables are Markdown and JSON files plus one Node script using node:fs and node:path. Path: write both templates -> write two minutes and their segment results -> write two summary results -> write the design note -> implement verify.js -> run node verify.js -> record the real output -> final hygiene check. The relative-date rule is deterministic: convert only when a meeting date exists, otherwise keep the original word and mark To Be Confirmed.
